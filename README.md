# GP-MPC Racing · 无人车竞赛

**v0.2调整：优先保留原程序和原地图，Python试跑不再充当原版替代品。**

为“智能制造课程设计”准备的独立课程扩展：**蓝车为教师 GP-MPC，橙车为学生控制器**。固定车辆和赛道，自动评测、打榜、保存版本，并在网页回放真实仿真轨迹。

## 原程序优先：先看这两个目录

- **`matlab_original/GP_MPC_Desktop_V3/`**：用户上传压缩包中的36个文件逐字节保留；NMPC、GP、车辆动力学、代价函数、原入口和说明均不改写。`matlab_original/MANIFEST.json`列出各文件SHA-256。
- **`matlab_web/`**：独立适配层，调用原MATLAB的`RaceTrack`导出地图，读取原`run_learning`输出，生成网页双车回放。原7维状态、3维控制、逐圈日志与配置保留。

默认地图已恢复为**原项目Track02**：20段原直道/圆弧指令、6m宽度、0.5m直线采样、5°圆弧采样，共391点；网页直接绘制原左右边界，不平滑、不拉伸、不以椭圆代替。静态地图按原算法逐点翻译生成；`selftest_web_export.m`可在MATLAB中与原类输出交叉核对，未宣称已在本开发环境执行该原生检查。

网页最上方可导入原MATLAB程序导出的双车JSON。导入在浏览器本地展示，不执行代码、不用Python重算轨迹，也不进入正式成绩。原输出未记录的每步预测轨迹不会凭空补出。具体操作见[原版运行与导出说明](matlab_web/README.md)。

**原程序完整运行仍需你的MATLAB及原工具箱。** 原上传包的`selftest_v3`依赖缺失的`selftest_v2.m`，该缺失有记录，未冒充补齐或运行通过。

## 当前可以做什么

- 二维俯视双车、历史轨迹、MPC预测轨迹、速度曲线、圈速、GP启用状态。
- 播放、暂停、倍速、拖动时间轴；两车互不碰撞，同一初始条件。
- 教师创建练习赛或结课赛、冻结规则、封存提交、发布或撤回成绩、重试异常和撤销成绩。
- 学生提交Python代码ZIP（≤1MB）、查看自己的版本与回放；代码与回放仅本人和教师可下载/访问。
- 独立gVisor评测机只接受控制量；车辆状态、圈数和成绩由可信裁判计算，网站再次逐步复核。
- 课程扩展使用原网站账号与课程权限，不再建立另一套学生账号。

浏览器打开 [http://127.0.0.1:8020/](http://127.0.0.1:8020/)。点击“计算双车对照”，计算结束后播放。默认先显示原Track02。可以直接导入MATLAB原版结果；下方Python移植试跑默认也使用原Track02，椭圆与连续弯道只作为显式另选的辅助地图。移植控制器不保证在原高难度地图完成，不能通过换地图来冒充原算法跑通。

这是本地可信控制器演示，不执行上传的任意代码、不产生正式成绩。GP-MPC计算可能慢于模拟时间，页面不会把计算等待伪装成车辆行驶。

## 来源与移植范围

参考用户提供的 `GP_MPC_Desktop_V3(2).zip`：全尺寸单轨车辆、名义/真实模型差异、10步NMPC、`[1,1,1,1,2,4]`分组、圈间残差GP训练与留出筛查。

这是**Python网页版工程移植**，不是MATLAB引擎，也不是逐点数值等价复现：

| 项目 | 网页版实现 |
|---|---|
| 车辆 | 6个物理状态；500kg真实模型、750kg名义模型、2.4m轴距；Pacejka真实侧向力、名义线性侧向力 |
| 物理执行器 | 转向和驱动力；第三个虚拟沿程速度仅供MPC内部优化，不作为第三个实车执行器 |
| 积分 | 固定0.15s控制周期，内部5个RK2子步；标准车体系科氏项，增加速度阻力 |
| NMPC | SciPy SLSQP替代fmincon；10步预测、18个分组变量、滚动热启动；增加弯道限速惩罚以适应严格车身边界 |
| GP | 5个特征预测3个离散速度/横摆残差；每圈前80%最多80点训练、末20%筛查，0.3增益，整体至少改善2%且单通道不能恶化超过5% |
| GP参数 | 每输出优化共享长度尺度倍率、信号与噪声；与原MATLAB逐维长度尺度优化不同 |

## 接到现有课程平台

在**网站服务器**解压/克隆本项目，进入项目根目录：

```bash
sudo bash deploy/install-course.sh
```

安装器要求已有 `/opt/writing-class` 和 `writingclass` 服务账号。它先备份数据库及服务配置，再安装独立扩展，通过systemd drop-in将入口切换为 `gp_mpc_racing.integrated:app`。原app.py、写作/英语/五子棋代码不作覆盖；失败时尝试自动恢复。

重新登录/刷新后，选择 **智能制造课程设计 → 无人车竞赛**。普通课程升级不会删除扩展目录或drop-in；但未来主平台接口变化仍需兼容性复核。

网站不安装SciPy、不执行学生Python；只使用既有FastAPI环境和标准库物理裁判。正式队列没有连接独立评测机时只保存作品，不显示模拟成绩。

### 独立评测机（正式比赛必需）

使用独立Linux虚拟机，先按Docker与gVisor官方说明安装运行时，不在有学生数据库和网站凭证的主机执行学生代码。

教师在网页“连接评测机”生成配置，保存为`worker.json`，不要放进GitHub、学生代码或聊天。

```bash
chmod 600 /私有路径/worker.json
sudo bash deploy/install-worker.sh /私有路径/worker.json
```

安装器要求runsc；构建镜像后先运行两个真实隔离容器，验证教师和入门模板完成2圈并重算轨迹，通过后才启动服务。缺少runsc或验收失败会停止，不降级为裸机执行。

手动验收：

```bash
docker build -t gp-mpc-racing:v1 .
RACE_WORK_DIR=/可被Docker绑定的私有目录 python -m gp_mpc_racing.smoke
```

每个控制器容器限制1核、768MB、64进程、无网络、只读根目录、非root、禁止提权。教师容器不挂载学生代码，学生容器不挂载其他作品或网站凭证。默认每步最多2s，跨圈时双方均额外允许20s训练计算；模拟步长仍为0.15s。整次任务最多30分钟，超限或教师接口异常不生成有效成绩。

**安全隔离须在目标评测机验收**。本地可信控制器测试不能替代Docker/gVisor验收。Docker管理权限只授予教师控制的评测机账号；不要在普通个人电脑上运行来源不明的参赛代码。

升级镜像、Python/SciPy、裁判、CPU/内核/runsc会改变环境指纹。已冻结比赛须恢复原环境，或另建比赛，不能把不同环境混在同一榜单。

## 学生代码接口

ZIP根目录必须有`agent.py`：

```python
from gp_mpc_racing.controllers import PursuitController

class Controller(PursuitController):
    def __init__(self):
        super().__init__(speed=8.0, lookahead=7.0)
```

可替换为自己的`Controller.act(observation)`。每次返回：

```python
{"steering": 0.2, "torque": 0.3}
```

- `steering`∈[-1,1]映射至±20°；`torque`∈[-1,1]，负为制动、正为驱动。
- `state`为`[x,y,yaw,vx,vy,yaw_rate]`；位置米、角度弧度、速度m/s。
- 观察还包含完整参考赛道、模拟时间、0.15s步长、已完成圈数和自己的上一次状态转移。这是完美状态观测教学赛，不是摄像头视觉赛。
- 可以保存类成员用于在线估计和圈间学习；同一轮保持同一控制器进程，新版本/新运行重置。
- 运行环境已有NumPy、SciPy；不支持联网安装依赖、MATLAB工具箱、GPU或二进制附件。
- ZIP只接受`.py/.json/.md/.txt`，最多50个条目、解压总计≤5MB；不接受路径穿越、加密、链接或重复条目。
- 不向标准输出打印调试信息：stdout保留给评测协议。过量输出、超时和非法控制量会失败。

## 排名与正式成绩

现有Python自动比赛仍是独立移植赛制，页面明确区分原MATLAB回放，不能将其成绩说成原MATLAB算法成绩。每场比赛固定一条赛道、一套工况、圈数、车辆和教师基准。第一版不宣称已有多赛道隐藏测试或相机观测。

1. 完成目标圈数者优先，按总模拟用时升序；同分并列。
2. 未完成者按净有效进度降序，再比较模拟用时。
3. 24个顺序沿程检查点、局部投影和物理位移约束共同计圈；不采信学生上报的圈数或坐标。
4. 每人最新已完成评测版本进入榜单；排队/基础设施失败不覆盖旧成绩。撤销最新成绩不会恢复更早版本排名。
5. 练习赛评测后可见；结课赛封存时选每人最后一个版本，全部评测后由教师发布，撤回发布后再次封存。
6. 榜单是比赛结果，不自动等于课程总成绩。GP状态、求解器自报信息仅为诊断，不作为评分证据。
